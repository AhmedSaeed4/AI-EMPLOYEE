# The File Was Named FINAL_approved_v9.mp4. It Was Not Final.

Every creative team knows this folder:

brief_v2.docx, brief_v2_NEW.docx, logo_final.ai, logo_final_fixed.ai, video_v3.mp4, video_v3_v4_FINAL.mp4.

It's funny right up until the wrong version gets published to 40,000 people.

Here's the part nobody says out loud: **that's not a naming problem. It's a systems problem.**

When nobody can tell which file is the source of truth, every review round gets slower, every revision costs more, and "final" becomes a hope instead of a status. The chaos doesn't stay in the folder — it shows up in your launch date.

We build creative production the way software teams build code:

**1. "Final" is an event, not a filename.** It has a date, an approver, and a version number. Nothing earns the word — it gets logged.

**2. One source of truth.** Every asset lives in a tracked pipeline: queued → in progress → pending approval → delivered. If it's not in the pipeline, it doesn't exist.

**3. Approvals are explicit.** The same gate we use for money and messages applies to creative. A human signs off, and that sign-off is recorded.

The teams that version like software deliver like software: on time, on spec, no surprises.

## Key Takeaways
- Naming chaos is a symptom — the disease is no single source of truth
- "Final" should be an approval event with a date and a name, never a guess
- Production systems are why some teams hit deadlines and others renegotiate them
